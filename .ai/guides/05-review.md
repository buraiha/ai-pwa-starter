# Review Guide

- taskの受け入れ条件を一つずつ照合する。
- Genpo固有語、固定テナント、秘密情報、実データが混入していないか確認する。
- 未送信データを失う経路、認証なし公開、無制限アップロードを重点確認する。
- `pnpm test`、`pnpm build`、`git diff --check` と必要な手動確認を記録する。
- 生成物、不要なlockfile差分、一時デバッグコードを成果物へ含めない。

## 共通ガイドの補足

実装レビューまたは完了前の自己レビューで使用する。

1. 要求と受け入れ条件に対する達成状況を確認する。
2. 作業ツリーと最終差分を確認し、既存変更と今回の変更を区別する。
3. 不要な変更、無関係な整形、一時コード、生成物、秘密情報がないか確認する。
4. 仕様、テスト、設定、ドキュメントの整合性を確認する。
5. 検証結果、既存問題、未確認事項、追加作業を明示する。

指摘は影響と根拠を示し、要求範囲外の問題は無断で修正しない。重要な未確認事項がある場合は、完全に検証済みとは報告しない。

設計書・要件正本と現行実装に不整合がある場合は、`.ai/common.md` の乖離レベル0〜3と停止・確認の規則に従う（パスはリポジトリルート基準）。文書か実装の一方へ推測で合わせない。
